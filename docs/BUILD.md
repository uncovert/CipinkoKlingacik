# Building and checking the design files

## Lightweight checks — any Python 3.10+

```sh
python3 -m unittest discover -s tests -v
python3 scripts/design_calculations.py
```

These inspect the included exports and source/artifact hash bindings. No Python
dependencies or KiCad are needed for this step. It is **not a fresh ERC/DRC run**.

## Full regeneration / ERC / DRC / exports

Install **KiCad 10.0.7**, Python 3.10+, Cairo's system library and `pdftoppm`
(Poppler). The current tested environment uses the **org.kicad.KiCad Flatpak**
with symbol, footprint and optional Packages3D library extensions. Native
`kicad-cli` is supported for checks; the stencil/return/field-sync helpers and
render path currently require the installed KiCad Flatpak Python API.

```sh
python3 -m venv .venv
.venv/bin/pip install -r scripts/requirements-hardware.txt
.venv/bin/python scripts/check_hardware.py
```

The pipeline regenerates the schematic twice and checks reproducibility, runs
ERC, exports netlist/BOM/drawings, runs strict PCB DRC/parity, regenerates the
prototype package and runs tests. No ignored PCB checks or unrouted override
are permitted. Netlist source paths are normalized to repository-relative paths.

Prototype export also generates the JLCPCB BOM/CPL, sourcing audit and budget
model offline from the pinned stock snapshot. See [JLCPCB.md](JLCPCB.md) for
upload instructions and procurement/rotation gates. Normal builds never query
or upload to JLCPCB, select alternates, or place orders.

**Ownership:** schematic/library/BOM files are generator-owned. Edit the two
generator/parts Python files, not just the `.kicad_sch`. The PCB is authoritative
and **is never regenerated by a seed/router script**. Normal checks do not
download assets or route a board.

## After an intentional PCB edit

```sh
.venv/bin/python scripts/check_pcb.py
flatpak run --command=python3 org.kicad.KiCad scripts/review_return_paths.py
.venv/bin/python scripts/check_pcb.py
.venv/bin/python scripts/render_pcba.py
.venv/bin/python scripts/check_hardware.py
```

Return review can add conservative local GND stitches and refill zones; it
requires a fresh clean DRC first and **must be followed by DRC again**. It is
not an EM/inductance solver. Re-render after any board/project change because
visuals are hash-bound. Review the schematic and manufactured outputs visually.

`scripts/sync_pcb_fields.py` supports explicitly approved metadata-only changes
with `--refs` and the expected current PCB SHA-256; it refuses changed footprint,
pin-net, population or schematic associations. Geometry/net changes require
deliberate PCB editing. `vendor_kicad_assets.py` is an explicit library upgrade,
never part of the normal build.

## Local release package

```sh
python3 scripts/package_release.py
```

This verifies sources/exports/docs/licences and runs the tests, then writes an
alpha ZIP and SHA-256 sums under ignored `dist/`. It never publishes, orders
hardware, creates a tag or changes qualification state. CI checks included
artifacts without KiCad; it does not pretend to rerun ERC/DRC.
